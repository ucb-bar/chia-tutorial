## Gotchas
  - Operand order: VectorIntFormat registers source regs in the order vs1, vs2, old-vd, but
    the ISA parser numbers operands by which of Vs1/Vs2/Vs3 your code mentions. If an OPMVV
    instruction's code doesn't mention Vs1 (e.g. vrev8, where vs1 is an opcode selector),
    Vs2 gets index 0 and silently reads the vs1 register. Check the generated
    build/RISCV/arch/riscv/generated/exec-ns.cc.inc for your instruction.
  - Element groups: vsha2* works on groups of 4 elements (EGS=4). vl is a multiple of 4 and
    groups never cross a vector register at VLEN=256, so compute a whole group when
    i % 4 == 0 and write Vd[i..i+3].

## Semantics, one element group, element 0 = rightmost in {}. Same structure for SEW=64.
  vsha2ms: {W3,W2,W1,W0}=vd; {W11,W10,W9,W4}=vs2; {W15,W14,W13,W12}=vs1
           W[t] = sig1(W[t-2]) + W[t-7] + sig0(W[t-15]) + W[t-16]   for t = 16..19
           vd = {W19,W18,W17,W16}
  vsha2ch/vsha2cl: {a,b,e,f}=vs2; {c,d,g,h}=vd
           KW = vs1 elements {3,2} for ch (element 2 first), {1,0} for cl (element 0 first)
           two rounds, for each kw in KW:
             T1 = h + sum1(e) + ch(e,f,g) + kw;  T2 = sum0(a) + maj(a,b,c)
             h=g; g=f; f=e; e=d+T1; d=c; c=b; b=a; a=T1+T2
           vd = {a,b,e,f}
