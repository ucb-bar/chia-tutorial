// of the destination buffer with SENTINEL.

        dst_buf[i] = SENTINEL;

    }
    return mismatches;

## Answer

### Design & Software-Hardware Interface

To maximize throughput across all copy sizes (`256B` to `16KiB`, both aligned and unaligned) while keeping invocation overhead minimal, we pack the destination address and copy length into a **single 64-bit register** and invoke the RoCC accelerator using a **single `custom0` (`funct=0`) instruction** with a register response (`ROCC_INSTRUCTION_DSS`):

1. **Single-Instruction Invocation (`opcode = 0`, `funct = 0`)**:
   - In Chipyard's bare-metal memory map, DRAM resides around `0x8000_0000` (well within the lower 32-bit physical address space) and `len` fits well within 32 bits (`0 <= len <= 16384`).
   - `rs1` (`a0` directly from the ABI call): `src` physical address (`uint64_t`).
   - `rs2`: `((uintptr_t)(uint32_t)dst) | ((uintptr_t)(uint32_t)len << 32)` — packs the 32-bit `dst` address in bits `[31:0]` and the 32-bit `len` in bits `[63:32]`.
   - `rd` (`ret`, returned in `a0`): The RoCC accelerator writes `1` to `io.resp` (`rd = cmd.bits.inst.rd`, `data = 1.U`) **only after** all memory reads and writes (including all TileLink acknowledgments / L1 cache writes) have completed, and simultaneously deasserts `io.busy`.
2. **Completion & Ordering without Extra Instructions**:
   - Because `memcpy_rocc` returns `ret` (which is bound to `rd` of `ROCC_INSTRUCTION_DSS`), Rocket's register scoreboard automatically stalls the `ret` (`jalr zero, 0(ra)`) or `csrr` instruction following the call until `io.resp` arrives from the accelerator, and returning `ret` directly in `a0` avoids loading an immediate `1` or executing a separate `fence` instruction.
   - Hardware also handles `len <= 0` immediately in 1 cycle by responding with `1` on `io.resp`.

```c

    uintptr_t ret;
    ROCC_INSTRUCTION_DSS(0, ret, (uintptr_t)src,
                         ((uintptr_t)(uint32_t)(uintptr_t)dst) | (((uintptr_t)(uint32_t)len) << 32), 0);
    return (int)ret;
    // ===== memcpy_rocc body: END =====
```

### Design & Software-Hardware Interface

To maximize throughput across all copy sizes (`256B` to `16KiB`, both aligned and unaligned) while keeping invocation overhead minimal, we pack the destination address and copy length into a **single 64-bit register** and invoke the RoCC accelerator using a **single `custom0` (`funct=0`) instruction** with a register response (`ROCC_INSTRUCTION_DSS`):

1. **Single-Instruction Invocation (`opcode = 0`, `funct = 0`)**:
   - In Chipyard's bare-metal memory map, DRAM resides around `0x8000_0000` (well within the lower 32-bit physical address space) and `len` fits well within 32 bits (`0 <= len <= 16384`).

   - `rs2`: `((uintptr_t)(uint32_t)dst) | ((uintptr_t)(uint32_t)len << 32)` — packs the 32-bit `dst` address in bits `[31:0]` and the 32-bit `len` in bits `[63:32]`.
