// and a trailing guard band. prepare() and check_copy() stay inside it.
static int span(int len, int src_off, int dst_off) {
    return PAD + (src_off > dst_off ? src_off : dst_off) + len + PAD;

// Fill the span of the source buffer with a seed-dependent pattern and
// of the destination buffer with SENTINEL.
static void prepare(int n, int seed) {
    for (int i = 0; i < n; i++) {
        src_buf[i] = pattern(i, seed);
        dst_buf[i] = SENTINEL;
    }
    asm volatile ("fence" ::: "memory");
}

// mismatch: a destination byte that differs from its source byte, a byte
// outside the destination range (in the guard bands) that is no longer
// SENTINEL, or a source byte that changed.
static int check_copy(int len, int src_off, int dst_off, int seed) {
    volatile uint8_t *s = src_buf;
    volatile uint8_t *d = dst_buf;
    int mismatches = 0;
    asm volatile ("fence" ::: "memory");

        if (s[i] != pattern(i, seed))

            if (d[i] != s[PAD + src_off + j])
                mismatches++;
        } else if (d[i] != SENTINEL) {
            mismatches++;
        }
    }
    return mismatches;
}

## Answer

### Hardware/Software Co-Design & Interface

1. **RoCC Instruction Interface (`custom0`, opcode `X = 0`)**:
   - **`funct = 0` (`ROCC_INSTRUCTION_SS(0, src, dst, 0)`)**: Latches the 64-bit physical source address `src` (`rs1`) and destination address `dst` (`rs2`) into accelerator registers.
   - **`funct = 1` (`ROCC_INSTRUCTION_S(0, len, 1)`)**: Passes the byte count `len` (`rs1`) and triggers the copy engine. If `len <= 0`, the accelerator completes immediately (`io.busy` remains `false`).

2. **Work Split & Memory Hierarchy Strategy**:
   - **Zero-branch software path**: Software issues the two `custom0` instructions unconditionally and synchronizes with a single `fence` before returning `1`. Avoiding software head/tail loops eliminates branch mispredictions and instruction fetch/decode overhead across all test and evaluation sizes.
   - **L1 D-Cache coherent datapath (`io.mem`) with hardware byte-alignment**: Because `prepare()` and `check_copy()` touch the buffers via the CPU immediately before and after `memcpy_rocc`, the working sets (`256B` to `16KiB`) are warm and dirty in Rocket's 32 KiB L1 D-Cache. The accelerator will operate through `io.mem` (`SimpleHellaCacheIF`) using 64-bit aligned loads, a hardware byte-shift/merge buffer for arbitrary `src`/`dst` misalignment, 64-bit aligned bulk stores, and sub-word/masked head and tail writes so no bytes outside `dst[0..len)` are modified.
   - **Completion Synchronization**: The accelerator keeps `io.busy` asserted until the L1 D-Cache acknowledges the final store (`io.mem.resp.valid`). Rocket stalls the `fence` instruction in the ID stage while `io.rocc.busy` is high (`RocketCore.scala`), guaranteeing all copied bytes are visible to subsequent ordinary loads before `memcpy_rocc` returns.
