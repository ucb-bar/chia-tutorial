### Key Hardware Optimizations over `iter_2`

1. **512-Byte Circular Byte FIFO & 16 TileLink Source IDs (`nReadIds = 8`, `nWriteIds = 8`)**:
   - Expanded the internal circular byte buffer from 128B (2 cache lines) to 512B (8 cache lines) and doubled the read/write source IDs to 8 each.
   - Allows up to 8 cache-line reads to be allocated and pipelined concurrently across L1 D-cache probe latencies and all 5 L2 `abc_mshrs` without stalling on FIFO allocation capacity.

2. **Full-Cache-Line (64B) Unaligned Read & Write Bursts (Eliminating 8B Stepping)**:
   - **Reads**: Whenever the remaining bytes in the current 64B cache line span more than a single 8B word, the read engine issues a single 64B-aligned `Get` (`lgSize = 6`) instead of up to seven separate 8B `Get` transactions, extracting only the active byte range `[rd_off_64B, rd_end_64B)` into the circular FIFO as beats arrive on Channel D.
   - **Writes**: Whenever an unaligned head or tail spans multiple 8B beats within a 64B cache line, the write engine issues a single 64B-aligned `PutPartialData` burst (`lgSize = 6`, 8 beats) with per-beat byte masks and barrel-shifted data, collapsing up to seven separate 8B L2 MSHR/probe transactions into one 64B transaction.

3. **Cut-Through (Wormhole) 64B Write Burst Initiation**:
   - Full 64B `PutFullData` bursts begin issuing on Channel A as soon as the first 8-byte beat is valid in the FIFO (`rot_valid(7, 0).andR`), immediately triggering the L2 directory lookup and L1 D-cache probe on beat 0 while the remaining 7 beats stream from Channel D through the FIFO to Channel A.
